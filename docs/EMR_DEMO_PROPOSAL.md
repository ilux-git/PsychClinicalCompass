# Предпросмотр JSON для ЭМК — предложение25.10

Основание: новое видение команды в [TEAM_VISION](TEAM_VISION_2026-10-25.md), U04. МИС пока эмулируется. Ниже конкретный проект контракта для брифинга; это **не реализованный экспорт, не согласованная схема внешней ЭМК и не юридическая ЭЦП**. Действующий коннектор МИС остаётся только для чтения.

## Минимальный пакет

```json
{
  "schema_version": "compass-emr-demo/1-draft",
  "synthetic": true,
  "patient_reference": {"system": "synthetic-mis", "id": "EXAMPLE-PATIENT"},
  "revision": 1,
  "section": "follow_up_observation",
  "content": {
    "source": {"type": "survey_submission", "id": "EXAMPLE-SOURCE", "version": 1},
    "observation": "Синтетический пример: пациент сообщил, что ему не подходит расписание.",
    "physician_action": "Обсудить удобное время контакта.",
    "verification": {"status": "pending", "basis": null}
  },
  "review": {"status": "pending", "actor_id": null, "reviewed_at": null},
  "destination": {"system": "emr-simulator", "status": "not_transferred"},
  "signature": {"kind": "simulation", "legally_valid": false}
}
```

Этот формат не пытается угадать `Kev/Tiny Jev`. Названия полей/разделов — предложение нашей команды, подлежащее отображению на реальную схему после её получения. Врачебное наблюдение, действие и отдельная проверка остаются разными полями; исходный ответ не переписывается.

## Последовательность будущей реализации

1. Лечащий врач выбирает разрешённый ему источник. Сервер проверяет роль **и связь с пациентом**; администратор/координатор не получают пакет.
2. Врач видит пациента, происхождение/версию, точный текст и раздел назначения. Личный дневник без разрешения не включается; не переносится вся карточка «на всякий случай».
3. Отдельное одобрение относится к точному неизменному содержимому/ревизии. Для него сохраняются автор, время и hash канонического содержимого. Изменение источника или текста требует нового предпросмотра/одобрения.
4. Только одобренный пакет может попасть в **синтетический приёмник**; повтор одного ключа не создаёт второй документ. Отклонённый/ожидающий пакет не передаётся. Одобрение и ответ приёмника — разные события.
5. В интерфейсе явно различаются «черновик», «одобрен врачом», «принят симулятором», «ошибка передачи». Последнее сохраняет одобренную ревизию для повтора. Подпись обозначена симуляцией, поле `legally_valid=false` сохраняется.

Проверка реализации: чужой пациент/роль не видят пакет; отказ/неполные сведения не превращаются в одобрение; изменённый hash требует нового решения; повтор/ошибка не размножают запись; никакой команды записи не уходит текущей read-only МИС. Это предметные будущие проверки, не уже пройденные тесты.

## Точный остаток U04

Для совместимости нужны расшифровка `Kev/Tiny Jev` и пример JSON/разделов внешней карты без персональных данных. Для реальной записи дополнительно нужны система/владелец, контракт идентификаторов/версий и подтверждённые полномочия/подпись. Пример выше уже можно обсуждать; повторного общего вопроса «что такое ЭМК» нет. [Общая очередь](OPEN_QUESTIONS.md).
