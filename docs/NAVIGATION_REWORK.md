# Навигация для первого знакомства · 24.10.2026

Обновление 24.10: браузерная страница приложения снова доступна. При доработке [главной пациента](PATIENT_HOME_PLAN.md) проверены собственные опросы/черновик, дневник/Back, альтернативный шаг с переносом фокуса, контекст скидки/подтверждения и три размера. Блокировка навигации при обмене сохраняет страницу и возвращает фокус после ответа. Это не завершает всю описанную ниже матрицу четырёх ролей; прежний browser URL policy-блок является историей. Новые свидетельства — [отчёт пациента](evidence/patient-home-2026-10-24/report.json).

Новое поручение после публикации `9e81115`: облегчить ориентацию на страницах всех ролей. Это отдельная локальная итерация; прежняя автономная разработка всего приложения не возобновляется. Медицинские правила, роли доступа, расчёты и схема БД не меняются.

## Проверяемый контракт

- Спокойный рабочий интерфейс, имеющиеся токены/компоненты/иконки; новые зависимости не добавляются.
- Целевые размеры: **375×844, 768×1024, 1440×1000**. Сначала доступен основной продуктовый шаг, без обязательной экскурсии.
- Врач: главная → пациенты → карточка → ответы/план → источник; пациент: мой день → опрос → история либо дневник/связь; администратор: обзор → затруднения → действия → данные; координатор: поручено → в работе → выполнено, проверка врача отдельно.
- Меню и помощь доступны с клавиатуры, текущая страница отмечена `aria-current`; закрытие диалога возвращает фокус. Симулятор остаётся явно демонстрационным.
- Несохранённый ввод и отправляемый запрос продолжают защищаться. При отмене Back должны совпадать сохранённая форма, URL и видимая страница. После завершения запроса отложенный переход самопроизвольно не выполняется.
- Для вкладок той же карточки используется прежняя защита `patient-card-tab`, чтобы ввод в постоянно видимой соседней форме не вызывал лишнего предупреждения.
- URL содержит только раздел/ID/вкладку; `history.state` — ID владельца и ограниченный навигационный контекст. Ответы, заметки, токены и черновики туда не передаются. При смене аккаунта прежний контекст не восстанавливается. API остаётся окончательной проверкой роли и связи с пациентом.
- Открытая форма опроса удерживает начальный снимок назначения: опрос списка в фоне не должен заменить её содержимое при ответе в другом окне. Реальная проверка этого поведения в двух окнах ещё входит в браузерную матрицу.

## Состояния и безопасный следующий шаг

| Состояние | Поведение |
|---|---|
| Загрузка прямой ссылки | Загружается актуальная разрешённая карточка/список назначений; неизвестность не становится пустым результатом |
| Ошибка загрузки назначения | «Не удалось загрузить опрос», повтор и переход к списку; отсутствие ещё не доказано |
| Назначение отсутствует в полученном списке | «Опрос недоступен», возврат к своим опросам; чужие ответы не подставляются |
| Недопустимый раздел роли/ID | Нормализация к доступной странице; индивидуальные данные всё равно проверяет сервер |
| Есть несохранённый ввод | Существующее подтверждение ухода; Back предварительно возвращается к текущему адресу |
| Отправляется запрос | Уход заблокирован; по завершении переход нужно выбрать заново |
| Успешный переход | Обновляются адрес, название вкладки браузера, текущий пункт и путь; при смене страницы фокус переходит к содержимому |

## Проверки и незавершённая приёмка

`npm run test:navigation` — 11 проверок маршрутов и истории: прямые ссылки/ID, роли, reload, Back/Forward, отмена и повтор ухода, карточка/вкладка, pending write, повторный клик, новая ветка Forward, отложенное действие после logout, очистка контекста и старые записи другого аккаунта. Это модель History API, не браузерный end-to-end проход.

TypeScript/Vite build проверяется после изменений. Сервер, миграции и клинические расчёты этой итерацией не меняются; 133 серверных теста публикационного снимка не называются проверкой новой навигации. В CI frontend добавлена команда проверки навигации.

Итоговые хеши, действующие файлы сборки, HTTP-проверки и явные незавершённые пункты — [машинный отчёт](evidence/navigation-2026-10-24.json). Проверка полноты визуальных свидетельств закономерно дала **NOT PASSED / exit 1**: новых снимков и реальных проверок размеров/фокуса нет. Успешная сборка и модельные тесты этот результат не подменяют.

**Браузерная/визуальная приёмка пока не выполнена:** существующая служебная страница ошибки заблокирована browser URL policy, обход не предпринимался. Пользователю отправлен отдельный запрос открыть приложение вручную. До появления разрешённой страницы нельзя объявлять проверенными реальные клики/фокус, размеры, fixed-панель, модальные окна и CSS на трёх ширинах. Матрица следующего прохода: четыре роли, первые шаги, клавиатура/меню/помощь, все три размера; несохранённая заметка/дневник/опрос + Back/Forward; refresh карточки/вкладки/назначения; источники/фильтры и смена аккаунта.

Прочие продуктовые решения остаются в [OPEN_QUESTIONS](OPEN_QUESTIONS.md). Для выбранной структуры навигации новых бизнес-уточнений не потребовалось. Коммит/push этой итерации не выполняется без отдельного поручения.
