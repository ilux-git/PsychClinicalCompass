Так сохраняется покрытие всех десяти исходных ID и отдельно остаётся срочный маршрут. В D03 два самостоятельных эпизода, поэтому три требуемые ситуации с Авиандром не растворяются в одной: пропуск, возможная НЯ, проверка совместимости D04. Их клиническая часть остаётся незакрытым C04; наличие формы/текста не означает реализованное правило.

## Одинаковый паспорт каждой истории

1. Синтетический профиль и связь с MIS ID, подтверждённые врачом диагноз/терапия/маршрут либо явное отсутствие данных.
2. Точные исходные события и их время, инструмент/версия/период; без подстановки нулевого ответа.
3. Ожидаемый результат системы, тип источника и версия правила; неподтверждённое правило выключено.
4. Решение врача, связанное действие и дата повторной проверки. Выполнение задачи и результат проверки различимы.
5. Ожидаемый агрегат и защищаемая группа; никакого вывода о причинности только по корреляции.
6. Альтернативная ветка: неполные данные, отказ доступа, повтор события, недоступность канала. Ожидание врача сохраняется, симуляция подписана.

## Следующие действия

Технический показ продолжается по [DEMO.md](DEMO.md). Для активации D01–D05 врачу передаётся именно эта матрица вместе с [C01–C06](CLINICAL_APPLICATION_PLAN.md#9-конкретные-уточнения-для-медицинского-согласования): утвердить применимые профили/формы, числовые условия, AV-основания и исполняемый маршрут. Общий вопрос «какие нужны сценарии» заново не задаётся. Пожелание будущего пилота16–40 не переписывает автоматически взрослые исходные профили/области применимости.
