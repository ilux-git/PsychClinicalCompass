# Демонстрация Clinical Compass · 25.10.2026

Все пациенты синтетические. Основной стенд: http://127.0.0.1:8780/. Участники/входы и запуск — [README](../README.md). Ниже порядок показа, а не измерение времени работы пользователей. Финальные новые экраны пока не прошли полную браузерную приёмку: [проверки и ограничения](VERIFICATION.md).

## Подготовка

- Убедиться, что `/health` сообщает обе БД ok и `synthetic_demo`. Войти под нужной ролью; проверять каждую роль отдельным входом. Обновить страницу, чтобы получить новую сборку.
- Выбрать у врача пациента с завершённым опросом о барьерах. Не удалять ответы ради повторения: при необходимости назначить новую версию/новый опрос.
- Для показательных агрегатов использовать только явно обозначенный синтетический порог. Скрытая группа не равна нулю; правило публикации нельзя обходить ради красивой цифры.

## Главная история: барьер → действие → проверка → аналитика

1. `doctor` → «Главная»: показать требующие действия задачи, ожидание проверки и проверенные результаты. «Открыть выполненные» ведёт к соответствующему этапу плана.
2. «Пациенты» → выбранная карточка → «Опросы и ответы». Показать исходный вопрос, дословный ответ, версию и отдельные даты. Причина пока является сообщением пациента, а не доказанной причиной ухода.
3. «Запланировать шаг». Источник остаётся рядом с формой; можно вернуться к нему. Задать конкретное организационное действие, исполнителя и контрольную дату. Клиническую работу оставлять врачу; координатору доступна только порученная организационная часть.
4. Описать реальное для учебного сценария действие → «Действие выполнено». Счётчик ожидания проверки меняется; результат ещё не объявляется известным.
5. Врач сохраняет «Сохранить проверку результата» с основанием: затруднение устранено / сохраняется / пока неизвестно. В последнем случае проверка выполнена, а результат неизвестен — это отдельные факты.
6. «Аналитика сопровождения» → действия/исходы: сверить изменение этапов. При сохраняющемся затруднении создать следующий шаг по тому же источнику. Одна выполненная задача не меняет автоматически статус лечения.

## Пациент: понятный вклад и добровольный игровой вид

1. Войти пациентом → «Мой день». Показать один доступный следующий шаг; сведения о лечении/визитах и история состояния отделены от баллов участия.
2. «Опросы врача» → назначенная форма → отправить ответы. Можно сохранить черновик и продолжить позже. После отправки показано подтверждение начисления из журнала: новое / прежнее при повторе / ноль / недоступная квитанция различаются.
3. «Мой дневник» → необязательная запись. Показать, что доступ врача выключен по умолчанию и включается отдельно. Честное наблюдение не требует «хорошего» самочувствия.
4. «Мой прогресс» → карта: открыть пояснение вехи. Карта зависит от накопленных баллов за всё время, обмен — от свободного баланса. Нет процента выздоровления, штрафа или рейтинга.
5. Выбрать «Мой ритм» и день: видны только учтённые действия/баллы за семь дней UTC. В «Спокойном режиме» — отдельный тихий вид без карты/серии, доступ к баллам и купонам остаётся.
6. Если свободного баланса достаточно, выбрать DEMO-купон и подтвердить резерв. Отмена возвращает резерв в свободный баланс; открытые места карты сохраняются. Коды DEMO не действуют в клинике.

## Врач: своя обратная связь без обязательного общего опроса

«Опросы для пациентов» → «Начать с редактируемого шаблона». Можно открыть анкету сопровождения или отдельный опрос об удобстве приложения. Изменить черновик → предпросмотр → сохранить → опубликовать → выбрать своих пациентов и назначить. Ни один шаблон не рассылается автоматически. Опубликованная версия неизменяема; новый вариант — отдельная версия. Оценка интерфейса не становится доверием к терапии.

## Руководитель / аналитик: без персональных карточек

1. `admin` → «Обзор клиники»: текущие подтверждённые отказы, явные обращения, ожидающие разбора, и выполненные действия без проверки. Это текущий срез, не показатель оттока за период.
2. «Причины затруднений»: статусы лечения и сообщённые причины отказов рядом с барьерами выполнения рекомендаций. Завершённое лечение, неответ и отказ не смешиваются.
3. «Действия и результаты»: действия, выполненная проверка и неизвестный результат различимы. Малые группы остаются скрытыми; нет цитат, ФИО и переходов к пациентам.
4. «Данные и приватность»: источники/синтетическая МИС и настраиваемый порог с основанием изменения. Эта роль не получает клинический доступ.

## Координатор и границы доступа

`coordinator` видит только свои организационные задачи, принимает/описывает действие. Клинические источники, приватные наблюдения и вывод проверки остаются у врача. `doctor2` видит свою когорту, пациент — собственные сведения. Приватный дневник не раскрывается врачу без выбора пациента. Внешняя Telegram-доставка помечена симуляцией, одобрение в Compass не выдаётся за запись в МИС.

## Клинический показ и незакрытые пункты

История PHQ-9/GAD-7, отдельные версии и исходные ответы доступны. При одной точке нет вычисленной динамики, при отсутствии наблюдений не подставляется ноль. Изменения баллов и участие не равны доказанному клиническому эффекту.

Предложение сократить P001–P010 до пяти историй: [матрица покрытия](CLINICAL_DEMO_COVERAGE.md). Числовые условия, конкретные формы, AV-сценарии и срочный внешний маршрут пока не активированы. Круглосуточное наблюдение, реальная скидка и реальная запись ЭМК не обещаются. Нагрузка1000одновременных/max500мс остаётся незакрытой инженерной проверкой. [Актуальные вопросы](OPEN_QUESTIONS.md).
