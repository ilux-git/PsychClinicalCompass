## Следующая независимая работа

1. Для ЭМК подготовлен [конкретный проект JSON и одобрения](EMR_DEMO_PROPOSAL.md); прикладной экспорт ещё не реализован. Хранить версию/источник/авторство, маркировать симуляцию. Одобрение не означает запись в реальную МИС или юридически действительную ЭЦП. Текущий read-only коннектор не расширять.
2. Подготовлена [матрица пяти историй](CLINICAL_DEMO_COVERAGE.md) с покрытием P001–P010; следующий шаг — согласование профилей/эпизодов с врачом. Назначения «Авиандра» брать из согласованных синтетических записей; новые дозы/противопоказания не выводить самостоятельно.
3. Реестр точных форм/редакций из КР и объяснимые предложения врачу — продолжить [клинический план](CLINICAL_APPLICATION_PLAN.md). Общая ссылка на КР не устраняет расхождения числовых правил C01–C04.
4. iPhone принят как первый внешний источник. Для HealthKit нужен отдельный нативный компонент и системное разрешение; веб-импорт JSON не выдавать за действующую интеграцию. Исследование API уже есть в [обзоре](INTEGRATIONS_RESEARCH.md); конкретный путь поставки остаётся U07.
5. Параметры реального пилота готовить как проект политики администратора. Предполагаемые16–40 лет не означают окончательно утверждённый возрастной диапазон. Не запускать автоматическое удаление/расширение доступа без принятой политики.

## Что ещё требует решения

U02/U03: точные формы, числовые условия и исполняемый срочный маршрут; пустые пункты и «Ы» в новом файле не являются ответом. Для пяти клинических историй нужно согласовать покрытие, а не просить придумать все сценарии заново. U04: точный формат/пример ЭМК и смысл `Kev/Tiny Jev`; до этого возможен явно демонстрационный контракт. U05/U06: политика реального пилота и условия реальных скидок. U07: владелец/поставка нативной iPhone-части. Подробности — [очередь](OPEN_QUESTIONS.md).
