# Дневники, Apple, Android и носимые устройства

Проверено **23.10.2026**. Это исследование вариантов и проектные предложения. Ни один внешний источник не подключён к Compass; разрешения аккаунтов, данные реальных пациентов и платные программы не запрашивались. API не тестировались на телефоне/часах. Научные основания — [R39–R44 и R50](RESEARCH_SOURCES.md), общая модель — [RESEARCH_REVIEW.md](RESEARCH_REVIEW.md).

## Что измеряют часы

Нужно различать три уровня: доступность исходного сигнала, точность измерения конкретного показателя и клиническую полезность его интерпретации. Успешная загрузка HR не проверяет ни HRV, ни тревогу. Это различие соответствует рамке [V3](https://www.nature.com/articles/s41746-020-0260-4).

Обзор Apple Watch 2026 года включает 82 исследования, но для HRV — лишь одно. Большая общая выборка не переносится на каждый показатель. Внешняя валидация проводится для определённой модели, режима, окна и популяции; её нельзя автоматически наследовать новому поколению устройства. [Lambe et al.](https://www.nature.com/articles/s41746-025-02238-1)

Пульс, HRV и vendor stress не взаимозаменяемы. Дыхание, физическая активность, положение тела и обработка артефактов влияют на интерпретацию. В обзоре тревоги 2026 года значительная часть результатов относится к небольшим лабораторным выборкам; независимые проверки и репрезентативность ограничены. Поэтому в MVP предлагается отображать происхождение измерения и динамику без диагноза или автоматической кризисной эскалации по часам. [Quigley et al.](https://doi.org/10.1111/psyp.14604), [Elgendi et al.](https://www.nature.com/articles/s43856-025-01234-6)

## Apple: три разных источника

| Источник | Что документировано | Путь к Compass | Существенное ограничение |
|---|---|---|---|
| Health / State of Mind | `HKStateOfMind`: моментная эмоция или настроение за день, valence, метки и ассоциации | Нативный компонент iPhone с HealthKit, разрешение на нужный тип, затем согласованная передача выбранных данных | SDK не валидирует нашу клиническую интерпретацию. Моментный ответ и итог дня нельзя смешивать |
| Journal | Личные записи и вложения; пользовательский экспорт ZIP, сохранение в PDF | Выбранный пользователем экспорт → предпросмотр → импорт после согласования формата | Архив может включать фото/места и другие избыточные данные; схема конкретного экспорта ещё не проверена |
| Journaling Suggestions | Системный интерфейс выбора события, которое человек хочет передать приложению | Нативный интерфейс выбора внутри iPhone-приложения | Не API фонового чтения всех записей Journal. Предложение события ещё не написанная пользователем запись |

Источники: [HKStateOfMind](https://developer.apple.com/documentation/healthkit/hkstateofmind), [авторизация HealthKit](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data), [экспорт Journal](https://support.apple.com/en-ca/121822), [Journaling Suggestions](https://developer.apple.com/documentation/JournalingSuggestions).

Текущий React-веб-интерфейс не получает HealthKit от добавления серверного маршрута. Для автоматического чтения нужен отдельный компонент совместимого Apple-приложения; тип State of Mind документирован начиная с iOS 18/watchOS 11. Разрешение запрашивается по типу данных и цели. Отсутствие полученных записей не даёт основания считать, что пациент ничего не заполнял: HealthKit намеренно не раскрывает приложению факт отказа в read-доступе так, как это позволило бы отличить его от отсутствия данных. [Документация HealthKit](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)

**Предложение:** для хакатона оставить собственный дневник основным маршрутом; для Journal сначала проверить один синтетический архив и минимальный перенос текста/дат. HealthKit — отдельная последующая задача с владельцем iOS-компонента. Не импортировать все вложения ради одной оценки настроения.

## Android: здоровье и дневник не составляют один API

[Health Connect](https://developer.android.com/health-and-fitness/health-connect/data-types) содержит HR, resting HR, HRV **RMSSD**, сон и сессии mindfulness. В проверенном каталоге не найден универсальный тип для произвольного настроения, текста личного дневника или vendor stress. Сессия mindfulness описывает занятие, а не психическое состояние и не доказанное выполнение терапии.

На Apple стандартный HRV-тип — **SDNN**. Это другая формула: одинаковые единицы `ms` не разрешают склеить их в одну линию. Нужны разные коды метрик и подписи. [Apple SDNN](https://developer.apple.com/documentation/healthkit/hkquantitytypeidentifier/heartratevariabilitysdnn), [Android RMSSD](https://developer.android.com/health-and-fitness/health-connect/data-types)

Health Connect требует Android-компонента и разрешений; фоновое чтение отдельно управляется пользователем. История, изменения, удаления и возобновление синхронизации требуют обработки. Само наличие приложения на телефоне не означает, что оно пишет нужный тип данных. [Синхронизация Health Connect](https://developer.android.com/health-and-fitness/health-connect/sync-data)

Не следует строить новую интеграцию на старом Fitbit Web API. В официальном объявлении Google от 29.09.2026 заявлен финальный срок **30.10.2026**; документы описывают Google Health API и повторный OAuth-consent при миграции. Старый поисковый снимок предупреждает об ограничении новых подключений, однако текущая главная страница уже предлагает инструкции новым разработчикам. Поэтому общий запрет новых проектов не утверждаем: доступ именно нашего приложения ещё предстоит проверить. [Объявление Google](https://support.google.com/googlehealth/blog/470464840/one-time-30-day-extension-for-fitbit-web-api-shutdown-and-demo-account-lifetime-adjustments?hl=en), [актуальная главная](https://developers.google.com/health), [миграция](https://developers.google.com/health/migration)

## Приложения для дневника, включая Android

Ни одно из перечислений не означает медицинскую рекомендацию, подтверждённое соответствие российскому контуру хранения или уже готовый импорт. Сведения о функциях получены от разработчиков; клиническая эффективность этих конкретных версий отдельно не проверена. Общие исследования письменных интервенций не валидируют произвольную шкалу приложения.

| Вариант | Данные и подтверждённый перенос | Пригодность для первого обмена | Что проверить на образце |
|---|---|---|---|
| **Дневник Compass**, веб на Android/iPhone | Уже есть текст, дата создания, личная/общая видимость | Самый короткий путь для собственного demo; медицинская шкала пока не введена | Отдельно согласовать шаблон, дату самого наблюдения, редактирование/удаление; нативной синхронизации нет |
| **Daylio**, Android/iOS | Настроение, активности/метки, заметки; документированы CSV/PDF | Кандидат на импорт выбранного CSV; простой пользовательский маршрут | Пользователь меняет словарь/иконки, поэтому значение mood не равно стандартной клинической шкале; локаль, время, повторы, версии категорий |
| **eMoods**, Android/iOS | Ручной `.emoods`-архив содержит CSV записей, лекарств, связок и заметок | Хороший кандидат на явное сопоставление дневника/лекарственного самоотчёта | Не импортировать перечень лекарств как врачебное назначение. Восстановить связи таблиц; дата дня не даёт точного времени приёма |
| **Bearable**, Android/iOS | Симптомы, настроение, факторы; CSV-экспорт. По FAQ читает Apple Health/Health Connect, но не пишет свои mood/symptom-записи обратно | Ручной экспорт, если этот дневник уже использует пациент | Нельзя обещать получить настроение Bearable через одно разрешение Health Connect; текущую схему CSV и представление «не заполнено/нет» |
| **Day One**, Android/iOS/другие платформы | На Android пакетные JSON/PDF/plain text/CSV; CSV содержит текст и дату, JSON может содержать дополнительные данные/медиа | Для общего письменного дневника; JSON после минимизации | Отличия платформ и одиночного/пакетного экспорта. Нужные записи/даты вместо всего журнала; вложения и геоданные не брать по умолчанию |

Первичные документы: [Daylio](https://daylio.net/), [eMoods](https://help.emoodtracker.com/article/20-importing-exporting-your-emoods-data), [Bearable: обмен](https://bearable.app/support/common-questions/can-i-write-or-import-data-to-another-app-from-bearable/) и [экспорт](https://bearable.app/chronic-pain-app-journal/), [Day One](https://dayoneapp.com/guides/tips-and-tutorials/exporting-entries/).

**Предложение для первого внешнего дневника:** один адаптер Daylio **или** eMoods, выбранный по фактическому использованию в клинике. Это альтернатива на первом техническом проходе, а не отказ от остальных направлений. Перед написанием парсера нужен синтетический файл точной версии экспорта; пока проверены документы, а не файлы/полнота переноса. CSV/PDF/JSON — это способы передачи, а не равные по смыслу измерения.

База SiA-WD помогает составить список, но не снимает ограничений API. [SiA-WD, 2025](https://link.springer.com/article/10.3758/s13428-025-02685-4)

|---|---|---|---|

| Fitbit / Pixel Watch; пример **Sense 2** в SiA-WD | Google Health API или фактически переданные типы Health Connect | HR/сон и документированные типы текущего API | Переход со старого Fitbit API; список данных и OAuth нужно проверять на новом API. | **Polar H10**, совместимые Polar-часы | AccessLink/поддерживаемая запись, отдельный мобильный путь для датчика | HR, RR или ночные показатели при поддержке выбранного устройства | H10 интересен для ограниченного исследования интервалов, но не является готовым бесшовным круглосуточным дневником стресса; условия записи и выгрузки обязательны |
| Другие устройства, включая Huawei/Xiaomi | Только после проверки конкретной модели/приложения/экспорта | Исходные измерения с определением и источником | Сам факт отображения «стресса» на экране не подтверждает API-доступ и клиническую валидность. **Предложение:** не делать закупку условием MVP. После основного врачебного workflow — одна существующая измерительная цепочка, выбранная по реальным устройствам команды/клиники; проверка источника, пропусков и согласия важнее объединённого «индекса стресса».

## Минимальный контракт импорта

Это спецификация следующей работы, не уже созданная таблица или новый маршрут API.

| Область | Необходимые сведения |
|---|---|
| Происхождение | Поставщик, приложение, модель, версия экспорта/алгоритма, внешний ID/версия записи, время импорта |
| Смысл | Код метрики, единица, SDNN/RMSSD/иная формула, исходное значение и исходная категория; личный словарь не заменять общим молча |
| Время | Время события отдельно от создания/получения, начало/конец окна, часовой пояс, точность даты; дата без времени не превращается в полночь как измерение |
| Качество | Известный режим/качество, пропуск, устройство не надето, нет разрешения или источник недоступен — насколько это реально различимо API |
| Повторы/изменения | Идемпотентный внешний ключ; обработка новой версии/удаления, повторный импорт без дублей; не смешивать переписанную и исходную запись |
| Доступ | Что пользователь выбрал передать, кому и для какой цели; импорт дневника личный до отдельного действия sharing; сведения не попадают admin как свободный текст |
| Минимизация | Предпросмотр полей/периода, отказ от фото/геолокации/контактов по умолчанию; сырой архив не сохраняется бессрочно без политики |

Одновременное поступление одного измерения через Health Connect и vendor API требует связи происхождения, иначе один пульс станет двумя наблюдениями. Не следует «усреднять» конфликтующие источники до анализа их смысла.

Протокол технической приёмки: синтетический файл/запись → предпросмотр → подтверждённый состав → импорт → повтор без дубля → изменение/отзыв доступа → пропуск остаётся неизвестным. Потом проверяется полезность врача и добровольность пациента. Только последний этап отвечает на вопрос, зачем клинике эта интеграция.

## Что остаётся для брифинга

Нужны фактический парк телефонов/устройств, используемые дневники и владелец нативного компонента; разрешённый контур внешних сервисов; политика хранения/удаления; желаемый клинический вопрос к измерению. Это уточнения для реального подключения. Исследование всех направлений выполнено; полная интеграция не объявляется результатом просмотра документации.
