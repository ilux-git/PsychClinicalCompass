# Новые синтетические клинические ответы

Отдельный явный запуск, не автоматическое заполнение при старте приложения. Источник: `app/db/fixtures/clinical_v1.json`, версия `synthetic-clinical/1`. Файл содержит вымышленные ответы для существующих десяти сценариев МИС; это не клинический отбор терапии.

## Что добавляется

Для семи активных профилей предусмотрены текущие PHQ-9, GAD-7 и панический PHQ: всего21 новый результат при исходно пустой клинической истории. Есть числовой0, разные суммы и обе ветки панического скрининга. Завершившим лечение, отказавшимся и профилю без данных новые формы автоматически не назначаются. Если текущий статус другого пациента изменён врачом, инициализатор учитывает его фактический статус.

Ответы проходят существующие неизменяемые бланки и сервисы назначения/отправки. Поэтому создаются обычные результаты, согласованные основания, outbox и баллы с действующим дневным пределом. Содержание симптомов и ветка не увеличивают награду. Worker создаёт события для ручного разбора; медицинское решение не генерируется.

На результате и в отдельном аудите сохраняются версия набора, SHA-256 исходника, сценарий и явный признак генерации. На главной пациента и в исходном историческом ответе показано, что это вымышленный пример для демонстрации.

В общих счётчиках назначений и завершений эти записи остаются. Из расчёта времени прохождения они исключены: скорость работы генератора не является скоростью пациента. Врач и администратор видят число исключённых примеров и оставшихся завершений. Админские показатели новых групп защищены той же политикой малых групп и дополнений.

## Как запустить

Из корня проекта в настроенном Python-окружении с переменными локальной демонстрационной БД:

```powershell
python -m app.db.seed_clinical
```

Это предварительный просмотр без записей. Сверьте `plan`, причины пропуска и `would_create_results`. Затем явное применение:

```powershell
python -m app.db.seed_clinical --apply
```

Для сохраняемого нативного стенда этого рабочего окружения используется тот же настроенный launcher:

```powershell
& work/venv/Scripts/python.exe -X utf8 work/run.py dev -m app.db.seed_clinical
& work/venv/Scripts/python.exe -X utf8 work/run.py dev -m app.db.seed_clinical --apply
```

`work/` не публикуется; другим участникам нужны собственное Python-окружение и переменные подключения. CLI принимает только локальную синтетическую среду с выключенными Telegram и нагрузочным режимом; базы с обычным производственным именем отклоняются. Он не предназначен для контейнерного или реального пилотного контура.

## Что сохраняется

- Стабильные ключи делают повтор идемпотентным. Конкурирующие запуски сериализуются; ответы, баллы и происхождение фиксируются одной транзакцией.
- Ручное клиническое назначение или результат этой версии не заменяется демо-ответом. Существующее взаимодействие с назначением и черновик также сохраняются. Конфликт содержимого или происхождения не перезаписывается.
- Старые числовые ответы не превращаются в валидированные измерения и не редактируются. Нет сброса базы, новых учётных записей, смены лечащего врача или записи в МИС.
- Время открытия остаётся неизвестным. Назначение и отправка происходят при генерации; короткий интервал между ними нельзя интерпретировать как скорость заполнения человеком.
- Не создаются исходное измерение по выбору врача, врачебное подтверждение, выполненная задача, факт медицинского контакта или успешный исход лечения. Один текущий ответ не выдаётся за историческую динамику.

Правила среды и узнаваемые профили уменьшают риск ошибочного запуска, но не распознают реальные сведения, вручную внесённые в демонстрационные аккаунты. Реальные данные в этом контуре не разрешены.
