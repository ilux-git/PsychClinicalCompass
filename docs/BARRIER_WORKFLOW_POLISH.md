# Барьер → действие → проверка → аналитика

Поручение 24.10.2026 после [разбора встречи](MEETING_REVIEW_2026-10-24.md). Пользователь утвердил основной сценарий и название «Мой прогресс»; повторное согласование этих решений не требуется.

## Контракт интерфейса

Врач начинает с известного факта пациента, видит его источник рядом с назначаемым действием, затем отдельно фиксирует работу и проверяет результат. Если затруднение сохраняется или результат неизвестен, доступен новый шаг по тому же источнику. Выполнение задачи не определяет исход лечения. Координатор выполняет только организационные поручения и не видит медицинский источник/основание проверки.

Рабочий интерфейс спокойный и компактный: один текущий шаг, читаемый основной текст, сроки/исполнитель рядом, второстепенные формы раскрываются. Сохраняются компоненты, токены и движение проекта. Аналитик сначала видит действия и полноту проверки, включая ожидающие проверки и неизвестный результат как разные категории. Период/знаменатель/ограничения остаются явными.

Размеры проверки: 375×844, 768×1024, 1440×1000. Проверить фокус, клавиатуру, длинный текст, отсутствие горизонтального переполнения, основные цели касания 44px, reduced-motion CSS. Loading — без ложного пустого списка; empty — следующий доступный шаг; error — ввод сохраняется и можно повторить; partial — доступные части остаются; success — виден результат и следующий этап; permission — нет удержания закрытых сведений.

## Три изменения

1. Название «Мой прогресс» и прямой переход от самоотчёта/ответа к действию с сохранением контекста и возвратом к источнику.
2. Последовательные формы действия и проверки, продолжение сопровождения после проверки, сохранение черновиков/ошибок/конфликтов.
3. Ясная аналитика этапов и результатов, предметная проверка полного синтетического маршрута и обновление документации/очереди.

Схемы БД, API, медицинские правила, тариф, доступ координатора и МИС не расширяются. Текущие ограничения C01–C06/U02/U03, реальная ЭМК/пилот/экономика и U09 сохраняются. План анализа не означает их исполнения. Commit/push в этом поручении не запрошены.

## Проверка и результат

Реализовано 24–25.10.2026. Врач видит исходный ответ рядом с действием и может вернуться к нему; работа и проверка результата разведены. После «не помогло»/«неизвестно» доступен новый шаг по тому же источнику. Приватные заметки и редактирование прежнего действия раскрываются по необходимости. Пациентский раздел называется «Мой прогресс».

| Было | Стало |
|---|---|
| Барьер отдельно от создаваемого действия | Контекст исходного ответа, дата и возврат к источнику |
| Выполненная работа смешивалась с результатом | Три этапа: действие → ожидание проверки → зафиксированный результат |
| `pending` включал ещё не выполненные действия | Ожидание проверки считается как выполненные минус проверенные; записанное «неизвестно» считается проверкой |
| В «Опросах и ответах» мелкие одинаковые строки и длинная цепочка дат | Заголовок 17px, вопрос 14px, ответ 16px; пары в двух колонках, даты под раскрытием, отдельная строка действий |
| На узком экране пары теряли связь | CSS переводит каждую пару «вопрос → ответ» в одну колонку; кнопки занимают строку. Финальный рендер этого исправления ещё не проверен |

Аналитика сначала показывает действия и полноту проверки; её знаменатели явные. Показатель проверки к текущему моменту не называется соблюдением сроков. Добавлены две группы защиты малых чисел: выполнено без проверки / выполнено с проверкой. Это исключает раскрытие малого остатка вычитанием безопасных на вид агрегатов; форма API не меняется.

Проверено: **137 backend tests /119.94s**, **20 frontend model tests**, TypeScript и production build. Синтетический маршрут в отдельной `compass_ui_flow_qa`: создание и проверка после управляемой ошибки 503 с сохранением ввода, возврат к точному самоотчёту, организационное поручение координатору, отдельная врачебная проверка. Сверка API: задач 32→35, выполнено 31→34, проверено 5→7, ожидают проверки 27; по одному новому `not_resolved` и `unknown`. Третья техническая задача завершена через API. Исход лечения остался `in_progress`. Администратор не получил исходные тексты или комментарий врача. Основная база не использовалась для этих клинических записей.

[Снимки и границы проверки](evidence/barrier-flow-2026-10-24/report.json). Ранние снимки подтверждают только перечисленные desktop-состояния, а не окончательный вид «Опросов и ответов». Финальная мобильная/планшетная матрица, admin/patient UI, последний фокус readonly-задачи, отложенный поиск и полный a11y остаются инженерными проверками. Computer Use остановился из-за неподдерживаемого контроля URL в текущем Windows-браузере; обход не использовался. Подмена дат автоматизацией также не подтвердилась: поля остались пустыми, сохранение введённых сроков не заявляется.

Локальный сервер и обе БД проверены через HTTP на8780; собранные JS/CSS доступны. Новых блокирующих бизнес-решений для этой итерации нет; прежние [вопросы](OPEN_QUESTIONS.md) сохраняются. Пользователь затем отдельно поручил продолжать развитие игрового стиля и оценку глазами клиники; это следующий объём работ.
