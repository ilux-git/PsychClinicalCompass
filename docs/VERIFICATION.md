## Применение уточнений и маршруты помощи — Phase 8

Актуальные функции/формулы — [MVP_WORKFLOWS.md](MVP_WORKFLOWS.md); оставшиеся решения — [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md). Ниже результаты текущей локальной реализации; прежние разделы сохраняют историю своих срезов.

- **103 passed in 49.32s**, без skips: итоговый полный pytest на PostgreSQL 16.15 после всех изменений сценариев/seed, описания аудита и подписей UI. Перед ним отдельно проверено подмножество seed/migrations, workflow analytics и care — **8 passed in 14.11s**; это часть тех же 103 проверок, не дополнительные уникальные тесты.
- Ручные исходы: собственный врач, append-only история/причина/автор, устаревшая revision и конкурентный повтор. Нельзя изменить чужого пациента либо вывести исход из молчания.
- Задачи: источник принадлежит пациенту и доступен врачу; организационная делегация только допустимому исполнителю, клиническая — лечащему врачу. Координатор получает только назначенные организационные задачи, без исходных клинических данных и приватного комментария проверки. Действие и проверенный результат независимы; повторы/аудит/запрет дальнейшей правки проверенного действия проверены.
- Лекарства: фиксированные/произвольные расписания, IANA timezone и периоды/версии, чужие роли/пациенты, конкурирующие запросы и исправление самоотчёта, будущие события и неоднозначные DST-времена. Пустое событие не становится пропуском; свободное расписание не создаёт обязательную дозу. На Windows добавлена `tzdata==2026.5`.
- Баллы: дневные пределы и конкуренция по разным действиям, rollback содержания вместе с начислением/аудитом, неизменность награды при разных симптомах/ответах/видимости дневника. Политика `demo-effort-v1`; старый seed не получает задние награды. Дневник проверяет время наблюдения и не превращает старое неизвестное время в факт.
- Admin: политика с optimistic revision/историей/основанием, роль только admin, начальное закрытое состояние, действительные разные пациенты/ячейки/дополнения и отсутствие индивидуальных текстов. Метрики проверены на наступивших сроках/полных окнах; ранний ответ будущей когорты не попадает в зрелый числитель. Исключающие варианты анкеты защищены API.
- Миграции `g25_care_workflow` → `h26_medication_schedule` → `i27_participation_privacy`: fresh/backfill/downgrade/upgrade на отдельной migration-test, native upgrade и `alembic check` без новых операций. На downgrade g25 сохраняется метка enum coordinator; действующим пользователям роль не переписывается. Рабочая МИС не мигрируется и остаётся SELECT-only.
- Production build TypeScript/Vite проходит, после последней правки текста bundle `index-2P7Csja-.js`. Локальный API перезапущен с актуальным JSON; health `ok`, обе БД доступны. Docker daemon локально недоступен. После приёмки пользователь поручил публикацию текущего пакета в рабочую ветку; прежний CI не подтверждает новый коммит автоматически.
- Документация: 21 UTF-8 документ, 136 локальных файловых ссылок, последовательности R55/T20/N9/U7 и синтаксис 120 внешних URL проверены без ошибок; `git diff --check` проходит. Это не повторный HTTP-тест всех научных источников.
