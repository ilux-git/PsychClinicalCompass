# Сбор аналитических данных по четырём направлениям

По изображению и уточнениям пользователя: все направления в работе, врачебные наблюдения только для врача. Не внедрялись психологические индексы, медицинские правила или несуществующая доставка/интеграции.

## Результат

- Вопросы размечаются readiness/approach_trust/constraints/recommendation_consistency; варианты препятствий имеют категории, опубликованная версия неизменяема. Вычисляются охват и исходные распределения, а не оценка личности.
- Отдельный первый показ пациентской формы в видимой вкладке, серверный аудит и идемпотентность. Воронка/медианы отличают неизвестные открытия старых ответов; назначение не выдано за отправку, wall-clock не выдан за активное время.
- Приватное наблюдение врача с направлением/автором/датой/источником; ручной переход из чата. Ответ пациента и баллы не перезаписываются.
- Добровольный текстовый дневник: личный по умолчанию, пациент управляет доступом лечащего врача; admin/чужие закрыты.
- Отдельные admin API/UI всех выбранных блоков, строго без индивидуальных строк/текстов/приватных источников и произвольных фильтров. Без политики групп значения скрыты; configurable suppression проверен по разным пациентам и дополнениям. Глобальное обезличивание одним порогом не объявляется доказанным.
- Документированы все семь источников, формулы и оставшиеся контракты; A01–A10 — новый конкретный список вопросов.

## Проверка

Полный PostgreSQL прогон **81 passed in 34.83s**, без skips; f24 migration/check/fresh/backfill/downgrade/upgrade. Production TypeScript/Vite build success.

Браузер: non-clinical demo-опрос patient6/7, patient6 отвечает по всем направлениям; охват каждого 1/2, один измеренный интервал open→submit 11,847 с, 10 старых завершений без вымышленного открытия. Две записи дневника — врач видит только общую. Сообщение → приватное наблюдение с автором/направлением/источником. Admin закрыт до политики групп. Mobile 390×844 проверен, viewport сброшен.

После новой схемы выполнен новый consistent snapshot restore в отдельную пустую `compass_collection_restore_test`: **19 таблиц/18 последовательностей** совпали, обе записи/видимость дневника сохранены; backup **0,197 с**, restore **0,375 с**. Это не промышленный RTO/RPO.

Подробные локальные JSON/снимки — outputs/. Новый source pipeline не опубликован и не объявляется проверенным прежним CI. Данные синтетические; исходный seed не менялся, native демонстрация добавлена отдельным авторским примером.
